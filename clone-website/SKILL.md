# Skill：把网站复刻成「全站内闭环」的静态站

## 触发场景
- 用户说「复刻这个网站」「仿一个这个页面」「把它存成静态站」「部署到我的域名/Pages」「把详情页也带上」。
- 目标：本地能开、结构还原、**所有可点内容都在站内自成闭环**，不把人甩回原站。
- 来源：为 Riven 复刻 Hacker News、HelloGitHub（含 60 个详情页 + 站内标签）等站点的实操经验。

## 硬性验收标准（定义「复刻完成」）
用户说「全部复刻」时，以下 6 条缺一不可，做不到的项必须在汇报里点明：
1. **列表卡片一律指向站内详情页**，不是原站外链（把卡片 `<a href="https://原站/...">` 改写为 `href="./repo/xxx.html"`，并给卡片加 `data-card="1"` 之类标记，同步改掉依赖旧选择器的筛选/过滤 JS）。
2. **详情页数量对得上列表条数**：列表有多少条，站内就生成多少张详情页，一张都不少（生成后必须打印计数核对）。
3. **标签页 / 分类页 / 作者页 / 分页 / 顶部导航 / 页脚**等所有入口也都指向站内页面；标签点进站内标签页，不点回原站。
4. **详情页提供唯一的外链出口**：一个「在 GitHub / 去原站查看 ↗」按钮（`target="_blank" rel="noopener"`），并在页内注明这是离线镜像、README 与源码去原站看。
5. **静态资源全本地化**：图片/CSS/JS/字体下载到 `assets/` 并改相对路径；除第 4 条白名单外，页面外链数为 0。
6. **脚本化校验**：部署后用脚本统计「站内链接数 / 仍外链数」，抽查详情页 200、含中文简介、「返回首页」可用，结果贴给用户。

## 部署域名约定（用户已定，不用再问）
- 复刻站统一挂在用户的 Cloudflare 自有域名 **senlinlu.cn** 下。
- 域名规则：**前缀沿用原站前缀 + 后缀 senlinlu.cn**。例：原站 `kaiyuanbang.cn` → 复刻站 `kaiyuanbang.senlinlu.cn`。
- 绑定方式：在项目 `wrangler.jsonc` 里加
  `"routes": [{ "pattern": "<前缀>.senlinlu.cn", "custom_domain": true }]`，
  然后 `npx wrangler deploy`，wrangler 自动建 DNS 记录，无需手动去面板添加。
- 同时保留 `"workers_dev": true`，让旧的 `*.workers.dev` 链接继续可用（否则加了 routes 后 workers.dev 会被自动禁用、老链接变 404）。
- 部署后用 `curl -s -D - "https://<前缀>.senlinlu.cn/"` 验证 200，并确认自定义响应头正常。
- 这是公开域名，任何拿到链接的人都能访问；用户要求私密时才加访问口令。

## 前置确认
- **自动获取（不要问用户）**：目标网址、项目目录（桌面 `<站名>-clone`）、部署仓库名与项目名按用户既有约定直接用，重复任务不再确认。
- **需要问用户的情况**：只在「复刻整站还是单页」「是否要上线到公网」信息真的缺、且猜错代价大时问一次，最好带推荐答案。
- 版权与合规：仅供个人学习/自用，不替换对方品牌、不冒用官方名义；上线时页面底部标注来源。

## 执行步骤
1. **取原页**：`open_application browser` → `open_url` 打开目标页并 `screen_snapshot` 确认；再用 `curl -L "<url>" -o raw.html` 拿原始 HTML（比渲染后的 DOM 更全）。
2. **摸清全站路由（决定要不要详情页）**：从列表页/`sitemap.xml` 抽出**所有条目链接与详情页 URL 模板**，写成 `repos.json`/`items.json`（含 owner/name、标题、URL）。列表条数就是详情页的应有数量。
3. **建目录与脚本**：`<站名>-clone/` 下 `site/`（成品，含 `repo/` 详情页与 `tag/` 标签页）、`assets/`（资源）、`detail-raw/`（原始详情页 HTML）；资源替换和详情页生成各写一个 Node 脚本，别手工改长 HTML。
4. **本地化资源**：脚本遍历 `src`/`href`/`srcset`/`url()`，逐个下载到 `assets/` 并改相对路径；失败的外链跳转、统计脚本、广告直接删标签，不留死链。
5. **批量抓详情页**：对每个条目 `fetch https://原站/详情路径`，要求 200 且含 `__NEXT_DATA__`（或结构化数据）才落盘；带 `User-Agent`，每次请求间 `sleep 500~700ms`，已存在且体积正常的文件跳过（可断点续跑）。
6. **解析结构化数据**：从 `__NEXT_DATA__` / JSON-LD 提取 `title / full_name / url / author / description / summary / primary_lang / lang_color / stars_str / forks / tags / updated_at / share_user`，存 `details.json`（先打一次字段名，防止取错路径）。
7. **生成站内详情页**：脚本套模板批量输出 `site/repo/<owner>__<name>.html`（扁平文件名避免深层目录），页内包含：`← 返回首页`（`../index.html`）、中文标题、仓库名、作者/语言/星标/Fork/更新时间/推荐人、简介卡片、标签、**唯一的「在 GitHub 上查看 ↗」按钮**、免责说明。复用站点既有 CSS 或内联样式保持一致观感。
8. **站内化改写首页**：脚本把卡片 `<a target="_blank" href="https://www.原站/...">` 替换为 `href="./repo/xxx.html" data-card="1"`，只替换存在于 `details.json` 的条目，其余（如页脚署名外链）保持不动并列表打印未匹配项；同步把依赖 `a[href^="https://原站"]` 的筛选 JS 选择器改为 `a[data-card]`。
8b. **生成站内标签页**：按标签聚合条目，每标签输出一页 `site/tag/<slug>.html`（页内卡片→`../repo/xxx.html`，标出数量），并输出 `site/tag/index.html`（全部标签 + 每标签条目数）。把详情页的标签、列表页侧栏/筛选里的标签统一改成 `../tag/<slug>.html`。
9. **本地校验（必做）**：`open_url file:///<绝对路径>/site/index.html` → `screen_snapshot` 核对样式/图片/字体，控制台无 404；点一张卡片进详情页，再点「返回首页」能回来。
10. **部署 + 线上校验**：`npx wrangler deploy`；然后跑校验脚本（Node fetch）输出：
    - 首页站内详情页链接数（应 = 条目数）、卡片仍外链数（应为白名单内数量）
    - 抽查 2~3 个详情页状态码、含中文简介、含「返回首页」「在 GitHub 上查看」
11. **汇报**：一句话给站内闭环结论（详情页 N 个 / 卡片全部站内 / 外链剩哪些）+ 本地路径 + 部署地址；未完成的说清卡在哪一步，不谎报完成。

## 命令与工具注意
- Windows 下 shell 别用 `&&`、`&` 串多条 node 命令，容易整体报错；一次跑一个脚本，输出重定向到日志再 `type 日志` 读（工具报 error 但消息里常有真实 stdout，按内容判断）。
- 批量抓取分成每批 20 条、带 sleep 跑，避免命令超时；超时就缩小批次继续，已完成文件靠「存在即跳过」续跑。
- 别为生成页面去开浏览器/Word（WPS）；普通站点用 Node + `write_file` 足够。
- 需要重新部署时用 `npx wrangler deploy`，不要手动删 DNS。

## 常见坑
- **侧栏「热门标签」留死链**：原站侧栏常是 `href="#"` 或是全站标签（本地数据集里根本没有），照抄就成了点不动的死链；必须按抓到的真实标签重建侧栏，并保证全站 `href="#"` 数量为 0。
- **卡片直接外链原站 = 没复刻**（就是这次的返工原因）：只扒了首页 HTML，卡片 href 还是 github.com，用户点一下就跑了。必须在第 8 步统一改写并校验外链数。
- 只存 HTML 不本地化资源 → 断网即白屏；详情页里的 `srcset`、CSS `background:url()` 最容易漏。
- 列表条数 ≠ 详情页数 → 计数核对，别凭感觉说「全部复刻好了」。
- 生成详情页时索引错位（用 `repos[1]` 当样本）会导致样本与标题不符，抓取和解析都要以 `owner/name` 为唯一键。
- 页面里的 `href="/xxx"` 绝对路径在本地会跳飞，统一改成相对路径或站内页面。
- 加 `routes` 自定义域名后 workers.dev 会默认关闭，要保留就显式写 `"workers_dev": true`。
- 改完 HTML 后旧的筛选/过滤脚本选择器会失效，页面看似正常但筛选全空，记得一起改。

## 自动更新（原站新增内容自动进站，可选）
用户要“每天自动同步原站”时，在项目里做一个 `update.js`，用系统计划任务定时跑，流程固定为：
1. 抓原站列表（优先用官方 API/结构化接口，其次解析首页卡片）→ 与本地数据文件比对，找出新增条目。
2. 只抓新增条目的详情页，缓存原始 HTML，老条目跳过；重新提取数据文件。
3. 重建数据驱动的页面（详情页、标签页），把新增卡片按站内链接插入首页（新卡片一开始就写成 `./repo/xxx.html` + `data-card="1"`，不要留原站/外链）。
4. **本地校验通过才部署**：死链 `href="#"` 必须为 0、站内链接指向的文件必须都存在；校验不过就终止，并把改动前的文件备份到 `backup/时间戳/` 供回滚。
5. 部署后做线上校验（首页站内链接数、随便抽一个新详情页、标签索引页返回码），全部写进 `update-log.txt`。
6. 备份目录只保留最近 7 份，避免无限增长。

Windows 计划任务注意：
- 用 `New-ScheduledTaskAction -Execute 'C:\Program Files\nodejs\node.exe' -Argument '"…\update.js"' -WorkingDirectory …` 注册；
  **不要**把带空格的项目路径直接塞进 `schtasks /TR`，它会在空格处拆成 Execute/Arguments，任务报 0x80070002「找不到指定的文件」。
- 批处理启动脚本必须写 **CRLF** 行尾，否则 cmd 会把多行拼错（报 “'dp0"' 不是内部或外部命令”）。
- 让 node 自己写日志文件；批处理 stdout 重定向到**另一个**文件，重定向到同一个日志会 EBUSY。
- 写 .ps1 时别用无 BOM 的 UTF-8 中文，PowerShell 5.1 会按 ANSI 读导致解析报错（改成英文输出或用 BOM）。
