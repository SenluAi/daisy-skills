# Skill：把网站复刻成「全站内闭环」的静态站

## 触发场景
- 用户说「复刻这个网站」「仿一个这个页面」「把它存成静态站」「部署到我的域名/Pages」「把详情页也带上」。
- **默认按整站理解**：首页 + 所有栏目页 + 所有列表视图（tab/筛选）+ 全部详情页；用户只想要单页时他会明说。
- 目标：本地能开、结构还原、**所有可点内容都在站内自成闭环**，不把人甩回原站。
- 来源：为 Riven 复刻 Hacker News、HelloGitHub（60+ 详情页、标签页、榜单三榜、月刊 126 期、文章 20 篇）等站点的实操经验。

## 硬性验收标准（定义「复刻完成」）
用户说「全部复刻」时，以下 8 条缺一不可，做不到的项必须在汇报里点明：
1. **列表卡片一律指向站内详情页**，不是原站外链（把卡片 `<a href="https://原站/...">` 改写为 `href="./repo/xxx.html"`，并给卡片加 `data-card="1"` 之类标记，同步改掉依赖旧选择器的筛选/过滤 JS）。
2. **详情页数量对得上列表条数**：列表有多少条，站内就生成多少张详情页，一张都不少（生成后必须打印计数核对）。
3. **标签页 / 分类页 / 作者页 / 分页 / 顶部导航 / 页脚**等所有入口也都指向站内页面；标签点进站内标签页，不点回原站。
4. **导航栏与每个 tab 都能点开**：导航里的每个栏目、列表页和页面上的每个 tab（月度/年度/周榜、精选/全部、热门/新晋、按年份/按分类切换等）都必须有一个真实存在的站内 `.html` 目标页；**不允许保留 `?rank_by=monthly` 这类会回原站的参数链接，也不允许 `href="#"`、`javascript:` 假链接**。验收时数一遍：导航外链 0、tab 外链 0、`href="#"` 0。
5. **频道页成套产出**：对照上一步的入口清单逐个建页，常见组合——
   - `rank/index.html` 榜单，每个 tab（月度/年度/周榜）都是站内可达的页或锚点
   - `periodical/index.html` 系列/期刊目录 + 每期一页 `periodical/<期号>.html`
   - `article/index.html` 文章列表 + 每篇正文 `article/<slug>.html`
   - `list/index.html` 全部条目、`tag/index.html` 标签总览、（原站有则加）`search/index.html`
6. **详情页提供唯一的外链出口**：一个「在 GitHub / 去原站查看 ↗」按钮（`target="_blank" rel="noopener"`），并在页内注明这是离线镜像、README 与源码去原站看。
7. **静态资源全本地化**：图片/CSS/JS/字体下载到 `assets/` 并改相对路径；除第 6 条白名单外，页面外链数为 0。
8. **脚本化校验**：部署后用脚本统计「站内链接数 / 仍外链数 / `href="#"` 数」，逐个频道页与 tab 目标 URL 探测状态码，抽查详情页 200、含中文简介、「返回首页」可用，结果贴给用户。

## 部署域名约定（用户已定，不用再问）
- 复刻站统一挂在用户的 Cloudflare 自有域名 **senlinlu.cn** 下。
- 域名规则：**前缀沿用原站前缀 + 后缀 senlinlu.cn**。例：原站 `kaiyuanbang.cn` → 复刻站 `kaiyuanbang.senlinlu.cn`。
- 绑定方式：在项目 `wrangler.jsonc` 里加
  `"routes": [{ "pattern": "<前缀>.senlinlu.cn", "custom_domain": true }]`，
  然后 `npx wrangler deploy`，wrangler 自动建 DNS 记录，无需手动去面板添加。
- 同时保留 `"workers_dev": true`，让旧的 `*.workers.dev` 链接继续可用（否则加了 routes 后 workers.dev 会被自动禁用、老链接变 404）。
- 部署后用 `curl -s -D - "https://<前缀>.senlinlu.cn/"` 验证 200，并确认自定义响应头正常。
- 这是公开域名，任何拿到链接的人都能访问；用户要求私密时才加访问口令。

## 前置确认
- **自动获取（不要问用户）**：目标网址、项目目录（桌面 `<站名>-clone`）、部署仓库名与项目名按用户既有约定直接用，重复任务不再确认。
- **需要问用户的情况**：只在「是否要上线到公网」信息真的缺、且猜错代价大时问一次，最好带推荐答案。复刻范围默认整站，不再问「整站还是单页」。
- 版权与合规：仅供个人学习/自用，不替换对方品牌、不冒用官方名义；上线时页面底部标注来源。

## 执行步骤
1. **取原页**：`open_application browser` → `open_url` 打开目标页并 `screen_snapshot` 确认；再用 `curl -L "<url>" -o raw.html` 拿原始 HTML（比渲染后的 DOM 更全）。
2. **枚举全站入口（复刻范围由这一步决定，最容易漏）**：把原站当成一张图逐个列清——
   - 顶部导航、页脚、侧栏里的每个栏目链接（含下拉菜单里的项）
   - 列表页每个 tab 与筛选，并记下它们真实切换的 URL 参数（`?sort_by=featured`、`?rank_by=yearly`、`?period=weekly`…）
   - 分页、期号网格、系列/专题/年度归档入口
   - 详情页类型（项目详情、文章正文、期刊页、作者页…）
   产出 `routes.json`：入口名 → 站内目标路径 → 数据来源。**原站有几种 tab，站内就要有几张页面**；这一步漏掉的入口，上线后用户一定会点，然后抱怨「点不动」。
3. **摸清数据来源（SPA 必须做）**：优先找官方 API / 站内 JSON（`/api/...`、页面里的 `__NEXT_DATA__`、`/_next/data/*.json`、`sitemap.xml`）。Next.js 等前端渲染站的 HTML 只是空壳，翻页与 tab 都是客户端路由，靠存 HTML 抓不到多页数据。把每个入口对应的数据接口、参数取值、条数上限写进 `routes.json`。
4. **建目录与脚本**：`<站名>-clone/` 下 `site/`（成品，含 `repo/`、`tag/`、`rank/`、`periodical/`、`article/`、`list/`）、`assets/`（资源）、`detail-raw/`（原始详情页 HTML）；资源替换、详情页生成、频道页生成各写一个 Node 脚本，别手工改长 HTML。
5. **本地化资源**：脚本遍历 `src`/`href`/`srcset`/`url()`，逐个下载到 `assets/` 并改相对路径；失败的外链跳转、统计脚本、广告直接删标签，不留死链。
6. **批量抓详情页**：对每个条目 `fetch https://原站/详情路径`，要求 200 且含 `__NEXT_DATA__`（或结构化数据）才落盘；带 `User-Agent`，每次请求间 `sleep 500~700ms`，已存在且体积正常的文件跳过（可断点续跑）。
7. **解析结构化数据**：从 `__NEXT_DATA__` / JSON-LD 提取 `title / full_name / url / author / description / summary / primary_lang / lang_color / stars_str / forks / tags / updated_at / share_user`，存 `details.json`（先打一次字段名，防止取错路径）。
8. **生成站内详情页**：脚本套模板批量输出 `site/repo/<owner>__<name>.html`（扁平文件名避免深层目录），页内包含：`← 返回首页`（`../index.html`）、中文标题、仓库名、作者/语言/星标/Fork/更新时间/推荐人、简介卡片、标签、**唯一的「在 GitHub 上查看 ↗」按钮**、免责说明。复用站点既有 CSS 或内联样式保持一致观感。
9. **站内化改写首页**：脚本把卡片 `<a target="_blank" href="https://www.原站/...">` 替换为 `href="./repo/xxx.html" data-card="1"`，只替换存在于 `details.json` 的条目，其余（如页脚署名外链）保持不动并列表打印未匹配项；同步把依赖 `a[href^="https://原站"]` 的筛选 JS 选择器改为 `a[data-card]`。
9b. **生成站内标签页**：按标签聚合条目，每标签输出一页 `site/tag/<slug>.html`（页内卡片→`../repo/xxx.html`，标出数量），并输出 `site/tag/index.html`（全部标签 + 每标签条目数）。把详情页的标签、列表页侧栏/筛选里的标签统一改成 `../tag/<slug>.html`。
10. **生成频道页与 tab 页（全站复刻的关键一步）**：按第 2 步的 `routes.json` 写一个 `build-pages.js`，每个入口一页，落盘位置固定为 `site/rank/index.html`、`site/periodical/index.html` + `site/periodical/<期号>.html`、`site/article/index.html` + `site/article/<slug>.html`、`site/list/index.html`。要求：
    - **tab 一律用站内真链接**，如 `./rank/index.html`、`./periodical/index.html`，不要留 query 参数或 `#`；
    - 频道页里的条目卡片照第 9 步规则指站内详情页；
    - 顺手把首页/列表页里原有的导航与 tab `<a>` 统一改写成站内相对路径（对 HTML 做字符串替换时，把替换前后各打印一条匹配结果，确认真的替换到了）；
    - 数据不全的入口（例如原站 API 只放出最近 3 期的项目数据）做成「完整索引 + 该条跳原站」，并在汇报里说明哪一层是索引、哪一层是完整复刻。
11. **本地校验（必做）**：`open_url file:///<绝对路径>/site/index.html` → `screen_snapshot` 核对样式/图片/字体，控制台无 404；点一张卡片进详情页、点「返回首页」能回来；**逐个点导航与 tab**，确认都跳到站内页面而不是原站。
12. **部署 + 线上校验**：`npx wrangler deploy`；然后跑校验脚本（Node fetch）输出：
    - 首页/各频道页站内链接数、仍外链数、`href="#"` 数
    - 每个频道页与 tab 目标 URL 的状态码（应全为 200 或 307→200）
    - 抽查 2~3 个详情页、文章页、期刊页的状态码、含中文简介、含「返回首页」「在 GitHub 上查看」
13. **汇报**：一句话给全站闭环结论（栏目 N 个 / 详情页 N 个 / 卡片全部站内 / 哪些入口是索引跳原站 / 外链剩哪些）+ 本地路径 + 部署地址；未完成的说清卡在哪一步，不谎报完成。

## 命令与工具注意
- Windows 下 shell 别用 `&&`、`&` 串多条 node 命令，容易整体报错；一次跑一个脚本，输出重定向到日志再 `type 日志` 读（工具报 error 但消息里常有真实 stdout，按内容判断）。
- 批量抓取分成每批 20 条、带 sleep 跑，避免命令超时；超时就缩小批次继续，已完成文件靠「存在即跳过」续跑。
- 页面里的中文在 PowerShell 写文件时容易变问号：用 Node/`write_file` 写 UTF-8（无 BOM），别用 PowerShell here-string 拼中文。
- 别为生成页面去开浏览器/Word（WPS）；普通站点用 Node + `write_file` 足够。
- 需要重新部署时用 `npx wrangler deploy`，不要手动删 DNS。

## 常见坑
- **「只复刻了首页和详情页」是最大返工原因**：导航「月刊/榜单/文章」和「月度/年度」这些 tab 还是原站参数链接，用户点了一点动静都没有（跳回原站首页或原站刷新），反馈就是「这个点不动、那个点不了」。必须给每个 tab、每个栏目建独立站内页面，并在第 10 步后逐个点一遍验证。
- **SPA / Next.js 站点**：直接存 HTML 只有空壳，分页与 tab 是客户端路由；要从 API/JSON 拿数据，用「多页 + 真链接」重建，别指望原站的 JS 在离线也帮你渲染。
- **Cloudflare Pages 的 clean URL**：上传 `rank/index.html` 后，线上访问 `/rank/index.html` 会 307 跳到 `/rank/`，页面里写 `./rank/index.html` 完全没问题；但校验脚本要按无扩展名 URL（`/rank/`）检查，看到 307 不是出错。
- **侧栏「热门标签」留死链**：原站侧栏常是 `href="#"` 或是全站标签（本地数据集里根本没有），照抄就成了点不动的死链；必须按抓到的真实标签重建侧栏，并保证全站 `href="#"` 数量为 0。
- **卡片直接外链原站 = 没复刻**：只扒了首页 HTML，卡片 href 还是 github.com，用户点一下就跑了。必须在第 9 步统一改写并校验外链数。
- 只存 HTML 不本地化资源 → 断网即白屏；详情页里的 `srcset`、CSS `background:url()` 最容易漏。
- 列表条数 ≠ 详情页数 → 计数核对，别凭感觉说「全部复刻好了」。
- 生成详情页时索引错位（用 `repos[1]` 当样本）会导致样本与标题不符，抓取和解析都要以 `owner/name` 为唯一键。
- 页面里的 `href="/xxx"` 绝对路径在本地会跳飞，统一改成相对路径或站内页面。
- 加 `routes` 自定义域名后 workers.dev 会默认关闭，要保留就显式写 `"workers_dev": true`。
- 改完 HTML 后旧的筛选/过滤脚本选择器会失效，页面看似正常但筛选全空，记得一起改。

## 自动更新（原站新增内容自动进站，可选）
用户要“每天自动同步原站”时，在项目里做一个 `update.js`，用系统计划任务定时跑，流程固定为：
1. 抓原站列表（优先用官方 API/结构化接口，其次解析首页卡片）→ 与本地数据文件比对，找出新增条目。
2. 只抓新增条目的详情页，缓存原始 HTML，老条目跳过；重新提取数据文件。
3. 重建**所有**数据驱动的页面（详情页、标签页、榜单页、期刊页、文章页、全部条目页），把新增卡片按站内链接插入首页（新卡片一开始就写成 `./repo/xxx.html` + `data-card="1"`，不要留原站/外链）；频道页的 tab 链接同样保持站内。
4. **本地校验通过才部署**：死链 `href="#"` 必须为 0、站内链接指向的文件必须都存在、导航与 tab 外链为 0；校验不过就终止，并把改动前的文件备份到 `backup/时间戳/` 供回滚。
5. 部署后做线上校验（首页站内链接数、随便抽一个新详情页、标签/榜单/期刊索引页返回码），全部写进 `update-log.txt`。
6. 备份目录只保留最近 7 份，避免无限增长。

Windows 计划任务注意：
- 用 `New-ScheduledTaskAction -Execute 'C:\Program Files\nodejs\node.exe' -Argument '"…\update.js"' -WorkingDirectory …` 注册；
  **不要**把带空格的项目路径直接塞进 `schtasks /TR`，它会在空格处拆成 Execute/Arguments，任务报 0x80070002「找不到指定的文件」。
- 批处理启动脚本必须写 **CRLF** 行尾，否则 cmd 会把多行拼错（报 “'dp0\"' 不是内部或外部命令”）。
- 让 node 自己写日志文件；批处理 stdout 重定向到**另一个**文件，重定向到同一个日志会 EBUSY。
- 写 .ps1 时别用无 BOM 的 UTF-8 中文，PowerShell 5.1 会按 ANSI 读导致解析报错（改成英文输出或用 BOM）。
