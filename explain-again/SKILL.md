# Skill：听懂重讲

> 来源：改写自 mattpocock/skills 的 `wait-what`（原文归档在 `productivity/wait-what.md`）。
> 用途：一句话没落到用户耳朵里时，**停下来重讲**，而不是继续往下说。

## 触发场景
- 用户说「没听懂」「重讲一遍」「再说一遍」「你刚才说什么」「等一下，什么意思」。
- 用户明显答非所问、或反问刚讲过的概念 → 视为「上一条没落地」，自动启用。
- 适用条件：用户对**上一条回复**表达困惑；不适用于用户是让我换个方案的情况。

## 前置确认
- **自动获取（不要问用户）**：上一条回复讲了什么、当时在做什么任务；用户惯用词（如「南京江宁」「Daisy-Skills」「选中的文件」）直接沿用，不要换成听不懂的说法。
- **需要问用户的情况**：只在不知道用户卡在哪一层时，问一句「是没听清词，还是想听为什么」。

## 执行步骤
1. **停住**：不解释、不辩解、不继续原来的内容。完成判据：这条回复里没有推进原任务的新动作。
2. **补背景**（一句话）：为什么刚讲这个，让用户接得上。完成判据：用户能听懂「这是在说哪件事」。
3. **用大白话重讲**：一条回复只讲一个意思，句子短，术语换成日常说法；用户自己的专有名词照用。完成判据：核心信息不超过 2～3 句。
4. **收口**：问一句「这样清楚吗，要不要我从哪一步再讲一遍」。完成判据：把话头交回给用户，等他说「懂了 / 继续」才往下走。

## 常见坑
- 把原话原封不动再说一遍——那不算重讲，等于没救。
- 越讲越长、越讲越绕，或者用新术语解释旧术语。
- 用户只是要「听清」，我却开始解释设计理由；先给结论，理由等他要。
- 语音场景下别念长串数字、路径、英文缩写，能简写就简写。
