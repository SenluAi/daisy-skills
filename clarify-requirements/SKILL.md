# Skill：追问澄清（把需求问透再动手）

## 触发场景
- 用户提出的任务含糊、目标可能有多个方向，或要做的是「方案 / 系统 / 长期项目」。
- 用户说「你先问问我」「帮我想想」「这个怎么弄比较好」。
- 判断标准：动手前如果还有关键决策得靠猜，就启用本技能。

## 前置确认
- **事实我自己查**（文件、路径、版本、环境、依赖是否存在），绝不问用户我能自己查到的东西。
- 只问「只有用户能决定」的事：想要什么效果、优先级、取舍偏好。

## 执行步骤
1. 把任务拆成一棵**决策树**：每个决策下面挂着依赖它的子决策。
2. 每轮只问「前置条件都已确定」的那一层（**前沿**），一轮把前沿问完。
3. 每轮格式：
   ❓ **Q1 - 问题标题**：问题说明（可含多个选项）
   ➡️ 我的推荐答案
4. 用户答完 → 重新计算前沿，再问下一轮；依赖本轮未决问题的，放到下一轮。
5. 前沿清空（每个分支都确定、没有默默假设）后，向用户确认「达成共识了吗」，确认了才动手。

## 常见坑
- 一次只问一个问题 → 拖成十几轮，用户烦。
- 把事实性问题抛给用户（「文件在哪？」）→ 自己查。
- 用户没确认就开干 → 方向错了全白费。
